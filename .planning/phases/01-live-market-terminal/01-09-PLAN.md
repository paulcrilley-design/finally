Write priceStream.test.ts with fake timers and the new page tests first, confirm they fail, then implement.

lib/types.ts: `StreamStatus` of "connected", "reconnecting" and "disconnected".

lib/priceStream.ts per D-08 and research Pattern 5: move the EventSource handling out of useMarket.ts into `openPriceStream(onPrices, onStatus)`, which returns a cleanup function, with constants `DOWN_AFTER_MS = 10_000` and `RECREATE_AFTER_MS = 2_000`; keep the try/catch around message parsing.

Down-timer rule: the timer handle is the record that the stream is down. To mark the stream down, do nothing when the handle is already set; otherwise report reconnecting and store the handle of a DOWN_AFTER_MS timeout that reports disconnected. The timeout callback leaves the handle set. Only the open handler resets the handle to undefined (after clearing the timeout), so errors that arrive after the timer has fired, such as the browser's 1 s retries, report nothing and start no timer. Resetting the handle inside the callback would make the next retry report reconnecting again.

Mark the stream down once before the first connection and on every error. On open clear both timers and report connected. On error, after marking down, when readyState equals EventSource.CLOSED report disconnected, close that source, clear any pending retry and schedule a new connection after RECREATE_AFTER_MS. The returned cleanup clears both timers and closes the current source.

lib/useMarket.ts: status state starting at reconnecting; fetch the watchlist on mount and on every connected status; apply only the response to the latest request (request counter) and nothing after cleanup; a failed fetch keeps the rows already shown, and the error text appears only while there are no rows. Never clear prices on disconnect (D-07). Return rows, status and error.

Extend fakeEventSource.ts only where these tests need more than it offers.
